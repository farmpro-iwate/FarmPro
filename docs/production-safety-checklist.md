# FarmPro 本番公開前の安全設定

本番環境では、次の設定を現在の運用に合わせて確認します。

## 必須の基本環境変数

- `NODE_ENV=production`
- `FARMPRO_AUTH_SECRET`：十分に長いランダム文字列
- `FARMPRO_DATA_DIR`：永続ディスク上のデータ保存先
- `FARMPRO_ALLOWED_ORIGIN`：公開するFarmPro画面のHTTPS URL
- `PORT`：Renderなど公開サービス側から指定される場合は、その値を使用

## メール送信

- `RESEND_API_KEY`
- `FARMPRO_EMAIL_FROM`
- 登録確認コード・メール変更・パスワード再設定メールが送信できることを確認する

## Stripe

- `STRIPE_WEBHOOK_SECRET`：本番Webhook用
- `STRIPE_WEBHOOK_TEST_SECRET`：サンドボックスWebhookを併用する場合のみ
- 本番価格は月額のみ
  - Standard：2,750円（税込）/ 月
  - Pro：5,500円（税込）/ 月
- Stripeの有効な契約記録とFarmProのプラン表示が一致することを確認する

## 運営者管理

- `FARMPRO_OPERATOR_EMAILS`：運営者として許可するメールアドレス
- 一般利用者には「その他の管理 > 運営者」が表示されないことを確認する
- 運営者だけが「利用者管理」「銀行振込申込管理」を開けることを確認する

## 銀行振込

- `FARMPRO_BANK_TRANSFER_NOTIFICATION_EMAIL`：銀行振込申込の運営者通知先
- `FARMPRO_BANK_NAME`
- `FARMPRO_BANK_BRANCH`
- `FARMPRO_BANK_ACCOUNT_TYPE`
- `FARMPRO_BANK_ACCOUNT_NUMBER`
- `FARMPRO_BANK_ACCOUNT_HOLDER`
- `FARMPRO_BANK_TRANSFER_DUE_DAYS`

確認事項：

- 利用者へ振込先・金額・支払期限・受付番号がメール送信されること
- 運営者へ申込内容・支払期限が通知されること
- 入金確認前は有料プランを有効化しないこと
- 入金確認後に正しいプランへ有効化できること
- 銀行振込契約終了後にFreeへ戻せること
- 支払期限を過ぎた未入金申込は自動で「期限切れ / 自動取消済み」になること
- 期限切れ申込は有効化できないこと

## 安全ガード

- 本番で `FARMPRO_AUTH_SECRET` がない場合、サーバーは起動しない
- 本番で `FARMPRO_DATA_DIR` がない場合、サーバーは起動しない
- 本番で `FARMPRO_ALLOWED_ORIGIN` がない場合、サーバーは起動しない
- 本番で利用者ファイルが空の場合、既知のデモアカウントを自動作成しない
- 許可した画面URL以外からのAPIアクセスはCORSで拒否する
- 運営者権限はサーバー側で判定し、フロント側へ運営者メールアドレスを直書きしない
- 銀行口座情報はGitHubへ直書きせず、Renderの環境変数で管理する

## 公開前の確認

1. `FARMPRO_DATA_DIR` が永続ディスクを指していることを確認する
2. バックアップJSONを手元にも保存する
3. 公開URLから新規登録・ログインできることを確認する
4. 別農場のデータが表示されないことを確認する
5. 再起動後も利用者・牛台帳・販売データ・決済関連データが残ることを確認する
6. Free / Standard / Pro の頭数制限が現在の仕様どおりであることを確認する
   - Free：繁殖雌牛10頭まで
   - Standard：11〜50頭
   - Pro：51頭以上
7. Stripe決済後にFarmProのプランが自動反映されることを確認する
8. 銀行振込申込から入金確認・有効化・契約終了・期限切れ自動取消まで確認する
9. 利用規約・プライバシーポリシー・特定商取引法の表記が現在の料金・月額契約に一致していることを確認する
10. ヘルプが試用版表現ではなく、現在の本番利用案内になっていることを確認する

### 2026年11月1日の通常同期点検の継続範囲

ワクチンと分娩の今回の変更は、削除失敗・遅い応答・削除済み情報の取り込み・既存数値IDの維持を対象とする。
ワクチンの関連経費は既存の経費APIで確認・削除し、販売精算の台帳や認証・契約処理を変更しない。
ワクチン削除だけ完了して経費削除が失敗した場合は、その結果を画面で明示し、残った経費は経費管理で確認する。
分娩の取得は既存の二つの呼出し口を共通処理へ通し、取得・編集・削除を農場単位で直列化する。
削除済み分娩から子牛登録を開始しない。既に数値・文字列の両キーがある曖昧な記録を自動統合する変更は含めない。

以下は今回の修正で完了したと扱わない。読取り所見を次の隔離テストへ引き継ぐ。

- ワクチンのPUT失敗後の自動再送、および別端末で同時編集した際のサーバー側の条件付き更新。
- 治療のDELETE待機中に別タブで編集する順序、繁殖の遅いPUT/GET応答が現在行へ及ぼす影響。
- 牛・子牛の未送信編集、遅い応答、農場切替、牛の二つの送信経路と成功表示の対応（次節の限定修正・検証へ継続）。
- 各一覧の画面復帰・通信復帰時の更新契機と、項目別同期を持たない管理項目。

これらの読取り所見は、本番で不具合が発症した証拠や、全項目の双方向自動同期が完成した証拠ではない。
次の変更も対象を一つずつ再現してから行い、休止中の全体同期を一括で有効化しない。
今回の公開・実機確認の到達点は対象PRへ記録し、過去の受信成功や医薬品の実機双方向確認を取り消さない。

### 2026年11月1日の牛・子牛の通常同期

開始時の本線・確認済み公開版は `3e369952accc7f69d9d169fa690f78f7b09775ca`。
今回の対象は牛・子牛の正式保存、再送、通常取得、削除と、分娩からの子牛登録である。
牛の通常フォームは `/api/cattle/record-sync` の受理・内容一致だけで同期完了を判定する。
旧 `/api/cattle/:id/sync` への二重送信は行わない。既存の明示的な補完用APIは残す。
子牛は `/api/calves/record-sync` を使用し、全体スナップショットへの書込みや休止中の全体同期は追加しない。

正式保存した行には、このブラウザ・農場・利用者と変更前の内容を結び付けた未送信状態を同時に保存する。
通信失敗後も業務内容と元の保存日時を保持し、同じ同期IDへ再送する。
コピーされた未送信情報や、変更前の内容を照合できない既存行を自動送信対象にしない。
通常の受信で未送信行を上書き・削除せず、別端末との違いは保留表示に残す。
応答喪失後は、最後に送信した内容・保存日時との一致を取得で確認してから受理済みと扱う。
分娩から登録する子牛も同じ経路を使い、分娩との紐づけと未送信状態を一つの端末内トランザクションに保存する。

自動再送はホームと牛・子牛の通常画面の表示、復帰、通信回復時に限定する。
一覧は再取得だけを行い、同期結果の通知後に保留表示を更新する。定期的な全件送信は行わない。
受信・バックアップ・販売精算の画面では新しい自動再送を開始しない。
画面移動前に既に送信したHTTP要求を、サーバーで取り消せるという保証ではない。
通信には12秒の期限を設け、遅延応答でも別農場や処理後に変更された端末行へACKを書き戻さない。

サーバーは新規IDの `If-None-Match: *`、既存世代の `If-Match` を照合する。
競合は412（旧本文の世代指定は409）で拒否し、削除済みIDへの通常PUTによる復活も拒否する。
同じ受理済み内容の再応答や削除の再応答で、保存世代を進めない。
ただし、条件ヘッダーにも本文にも更新基準を持たない旧クライアントの通常更新は、互換性のため従来どおり許可する。
その旧経路の同時編集まで保護済みとは扱わず、PC・通常ブラウザ・PWAそれぞれで更新版を使用していることを実機確認時に区別する。

同期IDのない旧行は、個体識別番号などの矛盾を耳標番号だけの一致で解消しない。
曖昧な別IDを自動統合・一括削除せず、元の端末行を保持する。
Freeの保存は端末内で完了し、再送用の所有情報を作成しない。
