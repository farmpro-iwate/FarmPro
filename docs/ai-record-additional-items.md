# 「AIで記録」の追加項目

## 利用者の操作

「AIで記録」で登録したい内容を入力する。
「記録する項目」は「文章から選ぶ」のほか、利用者自身でも選択できる。
追加項目は読み取った入力候補を表示し、「登録画面で確認・修正する」から通常の新規登録画面へ進む。
原文を確認し、不足項目を補ってから、利用者がその画面の保存ボタンを押す。

| 新しく候補を引き継ぐ項目 | 確認する主な内容 |
| --- | --- |
| 医薬品の購入・入出庫 | 区分、日付、品名、分包などの単位・数量、金額、ロット |
| 受精卵の購入・入出庫 | 区分、日付、品名、受精卵番号、数量、金額、父牛・供卵牛 |
| 出荷・販売 | 対象、出荷・販売日、金額、販売先、状態 |
| 経費 | 支払日、内容、科目、金額、支払先・方法 |
| BLV検査 | 対象、検査日、結果、次回検査日 |
| 給与アラート対応 | 対象子牛、対応日、アラート、対応内容・状態 |
| 肥育移行 | 対象、開始日、開始体重、理由、飼養場所 |
| 牛の登録 | 耳標番号、名号、生年月日、性別、父母など |
| 子牛の登録 | 子牛番号、名号、生年月日、性別、体重、父母など |
| 飼料給与の記録 | 給与日、対象、飼料名、数量・単位、金額 |
| 治療・予防・処置の詳細 | 削蹄・去勢・繁殖治療等の区分、子牛を含む対象、実施日、薬剤・費用など |
| ワクチンの詳細 | 子牛を含む対象、ワクチン名、接種日、次回予定、費用・状態 |

従来の発情・授精・ET・妊娠鑑定・分娩・治療・ワクチン・飼料使用・飼料入庫の対話登録は維持する。
飼料使用は在庫からの出庫、飼料給与の記録は給与管理への登録として種類を区別する。
医薬品・受精卵の明示がある入力は、汎用の飼料入庫判定より先に扱う。
予定管理、給与目安表、月末棚卸など専用の計画・設定画面は今回の追加対象に含めない。

## 候補と保存の境界

- 候補作成は端末内で行う。入力に明示された日付・番号・数量・金額などを候補にする。
- 「今日」「昨日」は端末の現地日付を基準にする。誤った日付や曖昧な値を確定値として補わない。
- 読み取れない内容は原文で確認でき、利用者が通常フォームで入力・修正する。
- 個体ID、同期ID、経費連動チェック、在庫のバッチID等を候補から受け入れない。
- 医薬品の購入費用を経費にも登録するかは、通常フォームで利用者が選ぶ。
- 子牛の販売・給与アラートは台帳から対象を選ぶ。番号を内部IDとして使わない。
- 過去の販売で台帳に個体がない場合は、「台帳にない子牛として記録する」を明示的に選ぶ。
- 治療の農場在庫のロット・使用数量も、既存の在庫選択画面で指定する。
- 保存には既存の登録処理を使い、在庫・経費・販売精算の処理をAI画面へ複製しない。

## 下書きの取り込み

`recordFormDraft.ts` が種類ごとの許可項目、選択肢、日付、数字を検証する。
`recordFormIntent.ts` が入力文から候補を作り、利用者・農場を確定してから画面間で引き継ぐ。
渡す値は `location.state.farmproAiDraft` に限定し、業務データとして保存しない。
`useAiRecordFormDraft` で新規フォームを一度だけ初期化し、取り込み後は履歴の下書きを消費する。
利用者が修正した入力へ候補を繰り返し適用しない。

既存レコードの編集や、個体・予定から開く既存の入力を優先する。
候補作成時と異なる利用者・農場へ引き継がず、保存直前にも所有者を確認する。
対象区分を確認した治療・ワクチンの経費は、同じ番号の成牛・子牛がいても該当区分の台帳を使う。

## 検証

追加項目の解析、許可外フィールド、所有者の変更、新規だけへの反映、入力の保持、履歴の消費、
分包・小数・0円、明示保存前の登録API呼び出しがないこと、既存対話登録の互換性をテストする。
データは隔離した試験用のものを用い、本番正式データを操作しない。
対象コミット、全体テスト・CI・ビルドの結果は対応PRへ記録する。
