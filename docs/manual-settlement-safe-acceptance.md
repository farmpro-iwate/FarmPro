# PR #753 手入力精算の安全な実画面検証手順

## 前提
- 本番 `app.farmpro-app.jp`、既存 `farmpro-trial`、既存農場のバックアップは使わない。
- **既存 Render サービスのブランチ・ディスク・環境変数を変更しない。**
- 最初は開発用の別ブラウザ・別プロファイル（または完全に独立したローカル環境）で、架空の牛・架空の経費のみで確認する。既存の利用者データはインポートしない。
- 既存の `docs/manual-settlement-render-preview.yaml` は**有料サービスの設計案**であり、明示的な費用承認なしに適用しない。

## 追加費用なしの第一選択：ローカル操作確認
1. このPRのブランチを別作業ディレクトリで取得する。
2. `npm --prefix client ci` → `npm --prefix client run build` → `npm --prefix client run dev` でクライアントを起動する。
3. 独立したブラウザプロファイルを使用する。必要な場合だけ、同一PRブランチのサーバーをテスト用ディレクトリとテスト用認証秘密鍵で起動する。
4. 架空の販売済み牛の販売レコードと、同じ精算に属する架空の登録済み経費を入力する。
5. 販売編集画面から「精算登録」を開き、明細・差引金額・既存経費の紐づけを確認する。
6. 確認ダイアログには「新規経費だけが保存される件数・金額」が出ることを確認する。
7. 初回登録後、経費一覧で既存経費が変更されず、新規分のみが追加されたことを確認する。
8. 同じ販売IDで精算番号だけ変更して再度登録し、拒否されることを確認する。
9. PC幅・iPhone幅で横スクロール、入力欄、ボタンの折返し、警告表示を確認する。

## 実精算書の金額照合
- 牛：ふくこ、耳標5953（**データは架空環境内のテストレコード**）。
- 販売金額 712,800円、精算額 663,597円。
- 既存経費候補：ワクチン費 3,640円。新規の二重登録は禁止。
- 各控除項目・200円の相殺の仕訳は原本に照らして確認する。精算額が一致することだけで各費用科目・会計処理を正当化しない。
- 同じ記録を本番環境へコピーしない。実データ登録はリリース後に利用者が原本を確認してから。

## Renderに別環境が必要な場合
Renderの Free Web Service は利用可能だが、**永続ディスクを付けられず再起動でサーバー側データが消える**。専用の一時的な試験にしか使わないこと。
有料サービス（永続ディスク付き）が必要なら、追加料金の見積りとユーザー承認を先に得る。既存試用サービスを転用しない。

## 出荷判定
自動テスト/ビルド成功のみではマージしない。独立実機テスト、重複登録、戻る導線、データ差異、会計扱いの確認を完了してからレビューする。
