# 農場ストーリーの表示設定

## 操作と表示

ホームの「農場ストーリー」右上にある「表示設定」から、表示する記録の種類を選ぶ。
「保存」で反映し、「キャンセル」では変更前の選択を維持する。
「全選択」「全解除」「初期設定」も利用できる。

| 初期状態 | 選択できる項目 |
| --- | --- |
| 表示 | 牛の登録、子牛の登録、繁殖、分娩、治療・投薬、ワクチン、出荷・販売 |
| 非表示 | 医薬品の入出庫、受精卵の入出庫、飼料の入出庫、飼料給与、経費、BLV検査、給与アラート対応、肥育移行 |

現在の7種類を初期表示として引き継ぎ、追加の8種類は利用者が選んだときに表示する。
全解除の状態も保存できる。その場合は項目を選ぶ案内を表示する。
種類で絞り込んだ後、日付の新しい順に最初の40件を表示し、「続きを表示」で40件ずつ増やす。
取得した対象記録に、別途件数の上限や過去の期間制限は設けない。

## 設定の保存範囲

選択はこのブラウザ・端末内に、利用者と農場を区別して保存する。
PC、スマートフォンのブラウザ、PWAではそれぞれ選択する。
農場共通の業務設定や契約・プランは変更しない。

保存先は `farmpro.farmStoryCategories.v1:<farmId>:<userId>` のlocalStorageで、各IDを別々にエンコードする。
保存する内容はversionと種類IDだけ。記録の内容は保存しない。
破損した設定は初期値へ戻し、未知の種類IDは無視する。
利用者または農場を確認できない場合、設定を共通の匿名領域へ保存しない。
保存領域が使えない場合はエラーを表示し、入力中の選択を残す。

## 記録の読み取り

既存7種類の取得と実績の判定は従来の処理を維持する。
追加8種類は、この端末に保存・受信済みの記録を読み取る。
選択されていない追加種類は取得せず、医薬品と受精卵は同じ台帳を1回だけ読む。
追加種類の取得には同期付き一覧、原価の自動補正、在庫・経費の保存処理を呼ばない。
新しい同期方式、DBの変更、業務記録の作成・更新・削除は追加しない。

追加の記録は購入日・入出庫日・給与日・支払日・検査日・対応日・移行開始日で並べる。
保存日時を実施日に置き換えない。削除・取消、未検査、未対応、日付なし・不正日付・未来日は対象から外す。
単位、数量の増減、金額0、小数を表示に保持する。
記録の取得に失敗した場合は、対象項目と再読み込みの操作を表示し、0件とは区別する。
これは現在の記録から作る一覧であり、編集前や削除操作を蓄積する監査ログではない。

各追加項目から元の台帳・編集画面を開ける。
牛・子牛へのリンクは、この端末の台帳にある番号またはIDで照合してから表示する。
ホーム集計用に作られた子牛の表示IDをカルテURLへ使用しない。
個体を照合できないときも、元の台帳へのリンクは表示する。

## 利用者・農場の切り替え

利用者・農場が変わったときは、ホームと設定入力を新しい所有者の状態へ切り替える。
読み取り完了時と設定保存直前にも所有者を確認し、古い農場の結果を反映しない。
ホームを離れて戻る、画面・通信が復帰する、表示項目を保存する際に、選択した追加項目を読み直す。

## 回帰確認

- `farmStoryDisplaySettings.test.ts`：利用者・農場の分離、全解除の復元、キーの非衝突、設定破損、保存の失敗。
- `farmStoryAdditionalRecords.test.ts`：8種類の実績・単位・金額、除外条件、部分失敗、所有者変更、HTTPと業務DBへの書き込みがないこと。
- `Home.story-settings.test.tsx`：実際の設定画面による保存・取消、再表示、40件ずつの表示、元記録と個体へのリンク、旧農場の応答の破棄。
- 子牛の集計IDと台帳IDが食い違う条件で、修正前の誤リンクを再現し、台帳IDを使う修正後に正しいカルテへ移動することを確認する。

テストは隔離した端末データで行う。本番の正式記録の保存を、表示設定の確認に使わない。
公開するコミット、CIとビルド結果、公開版との照合は対象PRへ記録する。
