# Stripe通知の順序逆転による誤有効化の防止

整理日: 2026-10-07
対象: PR #688 / `agent/operator-free-account-delete-20261006`

## 今回の範囲

削除機能の公開前確認に残っていた「未登録契約の終了通知が先に届く場合」を修正する。
Stripeへ契約の終了・Checkout停止・返金を要求する実装ではない。署名確認済みの通知をFarmProが受け取った後の、ローカル状態の扱いだけを変更する。

`stripeCheckoutStopClient.ts` の作成と利用者一覧への削除UI接続が以前ブロックされた問題は未解消。この変更を、それらの代替実装・ブロック回避・完成として扱わない。PRはDraftを維持し、本線へマージしない。

## 再現した問題

変更前の `deactivateSubscription` は、ローカル台帳に契約IDがなければ何も記録せず終了し、その通知を処理済みにしていた。
この後に古い `checkout.session.completed` が届くと、新しい契約のように利用者のプランを有料へ変更できた。

再現テストhead: `1c0d8ef3b7520cbfc3a49a197f70e020f3b71bb8`
GitHub Actions: https://github.com/farmpro-iwate/FarmPro/actions/runs/37560842758

テスト191件中185件成功・6件失敗を確認した。中心となる順序逆転試験は、拒否を期待した古いCheckoutがHTTP 200になって失敗した。既存181件の試験は成功していた。

## 修正

- `stripeInactiveNoticeStore.ts` に、契約ID・最初に受け取った対象状態・イベントID・受信日時を保存する。氏名・メール・パスワード・牛の記録は保存しない。
- 保存先は専用の `stripe-inactive-notices`。ファイル名は契約IDのSHA-256で生成し、パスの直接指定を受け付けない。
- 対象の通知は `customer.subscription.deleted` と、`customer.subscription.updated` の `canceled` / `incomplete_expired` / `unpaid`。従来の有料停止判定の範囲を維持する。
- 通知の記録を、契約台帳・プランの変更とイベント処理済み記録より先に保存する。対象利用者やプランを特定できない契約でも、その関係を捏造しない。
- 後から届いたCheckoutは、利用者のプラン変更前にこの記録を確認して拒否する。メールだけの古い経路や別の利用者IDを送っても同じ契約IDでは有効化しない。
- 500件のイベント履歴から古い通知が落ちても、この記録は残る。旧コードが処理済みにした通知の再送でも、重複判定より前に記録を補う。
- 有効契約の要約でも記録を確認し、途中失敗や旧台帳のactive行だけを根拠に、その契約を有効と表示しない。
- 更新停止の予約 (`active` / `cancel_at_period_end: true`) は契約終了と扱わず、有料利用を維持する。
- 別の有効なカード契約や銀行振込契約があれば、それに基づくプランを維持する。

## 失敗時と制限

記録が壊れている、別IDの内容が入っている、サイズ超過、シンボリックリンク、書込失敗の場合は「記録なし」と扱わない。通知は成功扱いにせず、再試行・確認が必要な状態にする。

複数ファイルを一括して確定するデータベーストランザクションではない。たとえば契約台帳の更新後にプラン保存が失敗すると、通知は失敗となり、再送による再処理までプラン行が古いまま残り得る。全変更が巻き戻ったとは表示しない。今回の試験では、この途中状態から再試行できることと、古いCheckoutで上書きしないことを確認する。

`unpaid` は解約済みという意味ではない。この記録は古いCheckoutによる誤有効化を止めるための観測記録であり、Stripeの最新状態・未払い解消・返金済みを表すものではない。支払回復を正しく照合して利用を復旧する処理は別途必要で、未実装のまま自動復旧できると案内しない。

既存Webhookは本番・テストの署名を同じローカル台帳で扱う構成が残っている。今回も単一Stripeアカウントの契約IDをキーとし、複数アカウント・本番/テストを横断した台帳分離は実装していない。公開前に接続構成と分離を確認する。

過去に処理済みとなった通知をStripeから自動取得する移行処理は追加しない。再送も保存記録もない過去の全不整合を修復したとは扱わない。

## 検証

新規試験は `server/src/stripeWebhook.ordering.test.ts`。既存のnpm testに追加し、既存テストを削除・スキップしていない。

専用一時ディレクトリと127.0.0.1のHTTPを使用し、外部通信を拒否する。署名は試験専用の値で作成する。実Stripe API、実際の課金、利用者や農場データは操作しない。

順序逆転、契約終了予約との区別、500件履歴の入替え、モジュール再読込、同じ通知の再送、署名不正、記録の保存失敗・破損、他契約の維持を対象とする。追加で、旧処理済み通知の再送、契約台帳・プラン・処理済み履歴の各保存失敗と再試行、銀行年払い維持、記録の不正形式・リンク、通知の同時到着、メールだけの旧経路を確認する。

最終headの実行結果はPR本文に記録する。テスト成功を、未完成の削除・退会機能や実Stripe停止機能の完成扱いにしない。

## 外部の仕様確認

- https://docs.stripe.com/webhooks#event-ordering : イベントの到着順を前提にしない。
- https://docs.stripe.com/billing/subscriptions/overview#subscription-statuses : `unpaid` と終端状態は区別する。
