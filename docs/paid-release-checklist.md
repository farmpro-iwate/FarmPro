# FarmPro 有料版 販売開始チェックリスト

対象ブランチ: `agent/paid-version`

## 1. コード検証

- [x] client のテストが GitHub Actions で成功している
- [x] client のビルドが GitHub Actions で成功している
- [x] server のビルドが GitHub Actions で成功している
- [x] 有料版専用 Workflow `Validate paid version` が存在する

## 2. 契約プラン

- [x] Free / Standard / Pro の上限と機能差が定義されている
- [x] 本番では契約プランをサーバー側で判定する
- [x] 新規アカウント作成時に plan を指定できる
- [x] `user:plan` で契約変更・解約時の plan 更新ができる
- [x] Free へ戻しても既存データは削除しない
- [x] Free 上限超過時は新たな繁殖牛登録・昇格だけを制限する

## 3. 認証とクラウド

- [x] クラウド保存は Standard / Pro のみ利用できる
- [x] 未認証は 401、プラン不足は 403 として扱う
- [x] 403 でログイン状態を誤って破棄しない
- [x] 自動バックアップはログイン済み Standard / Pro のみ動作する
- [x] 復元時は自動バックアップ通知を発火させない
- [x] 複数端末同期は競合時に自動上書きしない
- [x] クラウド snapshot に revision を持たせ、古い revision からの保存を 409 Conflict で拒否する
- [x] 自動バックアップも revision 保護された同期 push を通す

## 4. 本番環境

- [ ] `NODE_ENV=production` を確認する
- [ ] `FARMPRO_AUTH_SECRET` が十分に長いランダム値になっていることを確認する
- [ ] `FARMPRO_DATA_DIR` が永続ディスクを指していることを確認する
- [ ] 単一 Render サービスでは `RENDER_EXTERNAL_URL` が利用できることを確認する
- [ ] 独自ドメインや別フロントエンドを使う場合は `FARMPRO_ALLOWED_ORIGIN` を明示設定する
- [ ] `/api/health` が 200 を返すことを確認する
- [ ] Render 再起動後も利用者・牛台帳・販売・クラウド snapshot が残ることを確認する

## 5. 販売開始時の運用

- [ ] 契約者の farmId / 農場名 / 氏名 / メールを確定する
- [ ] `npm run user:create -- ... --plan=standard|pro` でアカウントを作成する
- [ ] 初期パスワードを安全な方法で契約者へ伝える
- [ ] 契約変更時は `npm run user:plan -- --email=... --plan=...` を使う
- [ ] パスワード再発行時は既存の `user:password` を使う
- [ ] 契約台帳側で「メールアドレス・farmId・plan・契約開始日・支払状況」を管理する

## 6. 公開直前の実操作確認

- [ ] 本番URLからログインできる
- [ ] Free で11頭目の繁殖牛登録が止まる
- [ ] Standard で99頭まで、100頭目が止まる
- [ ] Pro で頭数上限により止まらない
- [ ] Standard / Pro で手動クラウド保存できる
- [ ] 別端末でクラウド復元できる
- [ ] 2端末で同時変更した場合、古い revision の自動バックアップが 409 で止まりデータを上書きしない
- [ ] Free へ変更するとクラウド機能が利用できなくなるが、既存クラウド snapshot は削除されない
- [ ] Standard / Pro に戻すと保存済みクラウド snapshot を再利用できる

## 7. 現時点で販売開始を妨げない後工程

- 決済サービスとの自動連携
- 契約管理画面の追加
- plan 変更の自動化
- より高度な競合マージ

これらは手動運用で代替できるため、初期販売の必須条件にはしない。

## 販売開始判断

コード側は、CI成功・認証・plan制御・クラウド保存・自動バックアップ・複数端末競合保護まで実装済み。
残る必須作業は、本番環境で上記「4. 本番環境」と「6. 公開直前の実操作確認」を実際に確認すること。
