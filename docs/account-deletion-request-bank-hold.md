# 削除の確認依頼・取消と銀行振込の新規受付停止

更新日: 2026-10-07
対象: PR #688 / `agent/operator-free-account-delete-20261006`

## 状態と今回の範囲

作業ブランチ上の実装。未公開。利用者が削除・退会を実行できる段階ではない。

今回つないだ処理は、**運営者による削除の確認依頼、受付状況の再取得、依頼の取り消し、その依頼が残る間の新しい銀行振込申込の拒否**。

「確認依頼」は実削除や有料契約の解約とは異なる。アカウントのactive・プラン、既存の契約期間、牛・農場データは依頼や取り消しで変更しない。対象の通常ログイン・既存データ利用は維持する。

**カード決済の新規受付停止は、この工程には含まない。** 既存Payment Linkや開始済みCheckoutを止めたとは表示しない。実削除APIは引き続き実消去を許可しない。確認依頼の保存だけで削除許可を与えない。

## 運営者API

| 操作 | 入口 | 結果 |
| --- | --- | --- |
| 受付状況 | `GET /api/operator/users/:id/deletion-request` | 状態のみ取得。依頼の自動作成はしない |
| 確認依頼 | `POST /api/operator/users/:id/deletion-request` | 初回202、同じ依頼の再送200。削除はしない |
| 指定依頼の取消 | `POST /api/operator/users/:id/deletion-request/cancel` | 200。指定した依頼だけを取消 |

全操作で現在の運営者権限を確認する。依頼対象は共有されていないFree利用者で、ローカルの契約・申込・決済履歴がないことを確認する。運営者自身・他の運営者・共有/旧共通農場・有料プランは対象外。旧契約の値を補完・書き換えない。

受付には `requestId`、`farmId`、`email`、確認時点の `revision`、`confirmed: true`、`bankApplicationHoldConfirmed: true` が必要。requestIdはUUID。対象メールの入力と「この依頼が残る間、新しい銀行振込申込を止める」確認を別に要求する。余分なforce等は受け付けない。

取消はrequestId・farmId・現在のemail・confirmedが必要。取消を契約審査と混ぜないため、受付後にカード契約が発生した場合や別の決済台帳が壊れている場合でも、本人情報と運営者権限を確認できれば取消可能。削除処理に既に入った対象は通常の取消から復活させない。

## 保存と同時更新

`FARMPRO_DATA_DIR/account-deletion-requests.json` に依頼を保存する。運営者のID、対象のID、農場ID、依頼番号、確認時点のダイジェスト、時刻、取消状態を保持する。メール原文・パスワード・農場記録はこのファイルに追加しない。

単一Nodeプロセスの既存JSONストアを前提に、銀行振込の読取・更新・書戻しを同じロック内に置く。新規申込の許可確認から台帳への保存までを分断しない。銀行振込の期限処理・有効化・一覧統合による書戻しも直列化する。

- 確認依頼が先に保存された場合、新規銀行振込申込は拒否する。申込レコードも受付メールも作らない。
- 銀行振込申込が先に保存された場合、その履歴によりFree専用の確認依頼を拒否する。
- 取消が先なら、その後の新規申込は通常の受付へ進む。新規申込が先でまだ保留中なら、その回の申込は拒否する。
- 同じ確認依頼の再送で、受付時刻や件数を増やさない。
- 古い取消の再送で、別の新しい確認依頼による停止を解除しない。
- 申込・取消の結果が不明なら受付状況を再取得する。保存後の応答失敗を「保存されていない」「取り消し済み」と推測しない。
- 依頼台帳が壊れている、読めない、上限を超える、シンボリックリンクの場合は空と見なさず停止する。

## 利用者に表示する説明

銀行振込申込が停止中の場合:

> アカウント削除の確認依頼中のため、新しい銀行振込申込は受け付けていません。申し込みを続ける場合は、運営者へ確認依頼の取り消しをお申し出ください。この操作で既存契約や農場データは変更していません。

運営者の受付結果:

> 削除の確認依頼を受け付け、新しい銀行振込申込の受付を停止しました。アカウントと農場データは削除していません。カード決済や既存契約の停止・解約は、この受付では行っていません。

取消後は「この依頼による銀行振込の新規受付停止を解除」と説明し、新しい申込・課金・自動更新を開始したとは表示しない。別の依頼が残っている場合は、受付停止の継続を返す。

これらはAPIの返答と画面接続時の原稿であり、公開中の利用者一覧へボタンを追加済みという意味ではない。
