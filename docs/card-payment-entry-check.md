# カード申込のアプリ内入口確認

整理日: 2026-10-07
対象: PR #688 / `agent/operator-free-account-delete-20261006`
状態: 作業ブランチ上。マージ・公開・実決済は未実施。

## この工程で接続した範囲

`PaidPlanApplicationPage` のカードボタンから、認証後の `POST /api/card-payment-entry` を呼ぶ。
従来のページ内で決済URLを組み立てる処理と、直接Payment Linkを開くアンカーは外す。

1. 利用者が規約確認と料金確認を行ってボタンを押す。
2. サーバーはログイン中のID・農場を基に、現在の登録情報と削除確認依頼を読み直す。
3. 削除確認依頼中ならURLを返さず409。情報を確認できなければ503。
4. 許可できる場合だけ、従来と同じプラン・金額の決済リンクを返す。
5. 画面側は申込内容・対象・リンク先を検証し、同じタブでStripeへ移動する。

カードは従来どおり月払い。Standard 2,750円、Pro 5,500円（税込）。今回は価格・既存Stripe商品・Webhook・実際の契約を変更しない。

## 安全な停止と画面動作

- ページの表示だけではカード入口を要求しない。ボタンには直接の決済URLを持たせない。
- 対象のID・メール・返却先URL・force等をリクエストで上書きさせない。
- サーバーは現在のメールを使用。クライアント側のログインID・農場・メール・トークンが確認前後で変われば移動しない。
- 送信中の二重押しを止める。プラン変更・確認解除・ページ離脱時は旧応答で移動しない。
- 通信失敗・時間超過・不正応答・価格不一致時はエラーを表示し、古いURLへフォールバックしない。
- 成功URLをストレージへ保存しない。再試行は新たなサーバー確認を行う。
- 許可するホスト・プラン別パス・対象パラメータを検証する。外部の任意URLへ転送しない。
- 銀行振込の画面導線は維持する。
- 同じ削除確認依頼が有効な間は、以前作成した銀行振込の停止に加え、新しいアプリ内カード入口も拒否する。依頼取消後のクリックは再確認する。

## 完了していない境界

**これはStripeの決済セッション発行・無効化ではなく、FarmPro画面からの新規移動を確認する処理。**
返すリンク自体は従来の共通Payment Linkであり、一時トークンや一回限りのリンクではない。

- 先に発行・コピーされたPayment Linkや、既に開いているCheckoutを無効化しない。
- 入口の確認後に削除依頼が受け付けられても、返却済みリンクを取り消したことにはならない。
- 別経路からの購入・契約・既存の自動更新・返金を停止する処理ではない。
- `stripeAdmissionControlled` は引き続きfalse。削除APIの実消去許可も引き続きfalse。
- `OperatorUsersPage.tsx` への削除UI接続はこの変更に含めない。以前の書込ブロックを別経路で回避しない。
- 本人退会・有料契約の終了処理・バックアップ消去期限は別工程。

実削除を有効にするには、利用者に紐付く決済受付と開始済みセッションを管理できる方式、および実際のStripe環境との照合が必要。今回の画面変更だけでその条件を満たしたとは判断しない。
