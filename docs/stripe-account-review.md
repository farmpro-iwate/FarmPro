# Stripeの読み取り専用アカウント照合

## 状態

PR #688の作業ブランチ上の実装。未公開。この文書は退会・削除が利用可能になったことを意味しない。

今回の目的は、FarmPro内に課金記録が無いことだけを根拠にせず、Stripeから取得した顧客・契約・Checkoutの情報も確認できるようにすること。照合結果は**証拠の一部**であり、削除許可ではない。

## 実装した入口

`GET /api/operator/users/:id/stripe-review`

- 認証済み運営者専用。
- 対象のIDからサーバーに保存されているメール・農場IDを読み取る。リクエストのメール・接続先・キー等で上書きしない。
- 運営者本人、有料プラン、共有農場、契約・申込・決済の履歴がある対象、削除処理中の対象では照合を開始しない。
- Stripeを読んでいる間は全農場のJSONロックを保持しない。
- 読み取り後に、対象のアカウント情報と運営者の利用権限を再確認する。途中で変わっていたら結果を破棄する。
- この入口ではアカウント、農場、プラン、契約、削除履歴を変更しない。
- 常に `canDelete: false` を返し、照合結果も常に `mayDelete: false`。削除処理を呼び出さない。

## 照合内容

最初に `GET /v1/account` で接続先アカウントを確認し、次に以下をページ送りして取得する。

1. 顧客: `GET /v1/customers`
2. 決済手続き: `GET /v1/checkout/sessions`
3. 契約: `GET /v1/subscriptions?status=all`

現在のメールアドレスは大文字小文字をそろえて照合する。顧客APIのemailフィルターは大文字小文字を区別するため、今回の実装では使用しない。`client_reference_id`、対応するメタデータ、顧客ID、契約IDでも関連を確認する。関連する過去の契約や完了・期限切れCheckoutも「記録あり」として返す。

CheckoutのIDは `cs_test_...` / `cs_live_...` を検証する。未完了で利用者を識別できないCheckoutも「対象外」と断定しない。

## 結果の意味

| state | 意味 |
| --- | --- |
| `unavailable` | 設定・認証・通信・応答・ページ上限等により照合できない。契約なしとは判断しない。 |
| `review_required` | 関連記録、または利用者不明の未完了Checkoutがある。内容の確認が必要。 |
| `no_match` | 今回取得できた情報に一致がなかっただけ。削除を許可する結果ではない。 |

確認時刻と環境（live/test）、関連件数のみを返す。Stripeの生の応答、顧客名・電話番号、APIキーを返さない。`scanComplete` は今回の対象APIのページ送りが完了したことだけを示す。

## 接続設定（本番に設定済みという意味ではない）

サーバー側の環境変数を使用する。

- `FARMPRO_STRIPE_REVIEW_KEY`: 照合専用の制限付きAPIキー。自身のアカウント取得、顧客、契約、Checkout Sessionsの読み取りに必要な権限だけを設定する。書込権限は付けない。
- `FARMPRO_STRIPE_REVIEW_ACCOUNT_ID`: 照合対象のStripeアカウントID（`acct_...`）。

本番モードのサーバーは `rk_live_...` のみを受け付ける。非本番の試験では `rk_test_...` を使用できる。`rk_` の接頭辞だけで読み取り専用権限であることを保証できるわけではなく、Stripe側の権限設定が必要。実装が発行するHTTP要求はGETだけ。

既存のWebhook署名シークレットは流用しない。キーをチャット、スクリーンショット、GitHub、クライアント側コードに書かない。利用時はサーバーの秘密情報として設定する。今回は実際のキーの作成・取得・設定や、実際のStripe APIへのアクセスを行っていない。

## 制限

- 全体15秒、各一覧10ページまで（1ページ最大100件）。ページ数・応答サイズを超えた場合は途中の件数を根拠にしない。
- 応答は1回最大2MiB。照合は同一プロセスで1件ずつ。リダイレクトを許可せず、接続先を `https://api.stripe.com` に固定する。
- 削除処理とStripeの外部決済を、一つの原子的な処理にする仕組みではない。
- 照合後に新しいPayment Linkを開くこと、照合中にデータが変わること、既にメールが変更されていること、別アカウントでの決済などを、この照合だけで排除できない。
- 請求書・返金・異議申立て等を網羅するものではない。現行仕様は関連履歴があればFree専用の削除対象から外す。
- Stripeのテストクロックに紐付く顧客・契約は、一覧の既定取得範囲に入らない場合がある。テスト環境のno_matchを本番契約不在の証明にしない。
- APIバージョンの想定外の応答は確認不能として停止する。今回、Stripeアカウント側のバージョンや設定は変更していない。

## 公開前に残る作業

1. 削除要求を受けた後の新規課金入口を閉じ、既存の決済手続き・外部契約と照合してから削除を許可する工程。今回のno_matchで既存Draft内の削除APIを許可してはならない。
2. 削除APIへの照合・最終確認の組み込み。既存Draftの `/delete` はまだこの照合結果を使用していないため、Draft全体を公開しない。
3. 利用者一覧への削除ボタンと一覧・件数更新。以前のツール安全確認でブロックされた画面組み込みは、今回再送・別経路実行していない。
4. 本人退会、カードの更新停止、有料契約中の退会、バックアップ保持期限、公開規約の整合。
