# FarmPro 有料プラン運営手順

対象: Standard / Pro の銀行振込による初期運用

## 基本方針

- 有料プランの申込は、FarmProの申込確認画面から受け付ける。
- 振込先口座は公開サイトや公開リポジトリには掲載しない。
- 振込先は申込者へ個別に案内する。
- 入金確認前にStandard / Proを有効化しない。
- 有料プランの有効化はRender Web Shellで行う。
- 利用者のパスワードを運営記録へ残さない。

## 1. 申込受付

申込が届いたら次を確認する。

- 農場名
- 利用者名
- メールアドレス
- 希望プラン: Standard / Pro
- 支払期間: 月額 / 年額
- 支払額

料金:

- Standard 月額: 1,650円（税込）
- Standard 年額: 18,150円（税込）
- Pro 月額: 3,300円（税込）
- Pro 年額: 36,300円（税込）

## 2. 振込先を個別案内

申込内容を確認後、申込者へ振込先を個別に案内する。

公開GitHub、販売サイト、アプリ内の公開ページには口座番号を記載しない。

案内時には最低限、次を伝える。

- 希望プラン
- 月額 / 年額
- 支払総額（税込）
- 振込期限
- 振込手数料は利用者負担
- 入金確認後にプランを有効化すること

## 3. 新規利用者の場合: アカウント作成

Render DashboardからFarmProサービスの Web Shell を開く。

`<...>` の部分を実際の申込内容へ置き換える。

```bash
npm --prefix server run user:create -- --farm-id <farm-id> --farm-name "<農場名>" --name "<利用者名>" --email <メールアドレス> --password "<初期パスワード>" --plan free
```

重要:

- 初回は `--plan free` で作成する。
- パスワードは8文字以上。
- パスワードをGitHub、申込台帳、チャット等へ保存しない。
- `farm-id` は半角英数字、`_`、`-` のみを使う。

成功すると農場ID、農場名、利用者名、メール、プランが表示される。

## 4. 入金確認

銀行口座で入金を確認する。

確認項目:

- 振込名義
- 入金額
- 希望プランと金額の一致
- 月額 / 年額の一致

金額が一致しない場合は、プランを有効化せず申込者へ確認する。

## 5. Standard / Pro を有効化

入金確認後、Render Web Shellで実行する。

Standard:

```bash
npm --prefix server run user:plan -- --email <メールアドレス> --plan standard
```

Pro:

```bash
npm --prefix server run user:plan -- --email <メールアドレス> --plan pro
```

成功すると次が表示される。

- 農場名
- 利用者名
- メール
- 更新後プラン

表示されたメールアドレスとプランが申込内容と一致していることを必ず確認する。

## 6. 利用開始連絡

プラン有効化後、申込者へ次を案内する。

- 入金確認済み
- Standard / Pro の有効化完了
- FarmProへログインすること
- 設定画面で契約プランを確認すること
- Standard / Proではクラウド保存、自動バックアップ、複数端末同期を利用できること

利用者が既にログイン中の場合、再読み込みまたは再ログインで最新プランを取得する。

## 7. 更新

現在の銀行振込運用では自動決済更新を行わない。

契約期間終了前に運営者から継続案内を行い、入金確認後に継続扱いとする。

月額契約: 1か月

年額契約: 1年

運営台帳には最低限、次を記録する。

- 農場名
- メールアドレス
- プラン
- 月額 / 年額
- 入金確認日
- 利用開始日
- 次回更新予定日

口座番号やパスワードは運営台帳へ記録しない。

## 8. 解約

利用者から解約申出があったら、次回更新を停止する。

支払済み期間の末日までは有料プランを利用可能とする。

利用期間終了後、Freeへ戻す場合:

```bash
npm --prefix server run user:plan -- --email <メールアドレス> --plan free
```

実行後、表示されたメールとプランが正しいことを確認する。

法令上必要な場合等を除き、利用期間途中の日割り返金は原則行わない。

## 9. プラン変更

StandardからProへ変更する場合などは、差額・開始日を申込者と確認し、入金確認後に `user:plan` を実行する。

```bash
npm --prefix server run user:plan -- --email <メールアドレス> --plan pro
```

ProからStandardへ変更する場合は、Standardの99頭上限に収まることを確認してから変更する。

## 10. エラー時

代表的なエラー:

- `USER_NOT_FOUND`: 指定メールの利用者が存在しない。メールアドレスを確認する。
- `INVALID_PLAN`: `free` / `standard` / `pro` 以外を指定している。
- `PASSWORD_TOO_SHORT`: 新規作成時のパスワードが8文字未満。
- `EMAIL_ALREADY_EXISTS`: 同じメールのアカウントが既に存在する。新規作成せず、既存アカウントのプラン変更を使う。

不明なエラーが出た場合は、同じコマンドを何度も実行せず、表示内容を確認してから対応する。

## 1件の申込を処理する最短チェック

1. 申込内容を確認
2. 振込先を個別案内
3. 新規ならFreeアカウントを作成
4. 入金確認
5. `user:plan` でStandard / Proへ変更
6. 出力されたメール・プランを確認
7. 利用開始を連絡
8. 次回更新予定日を運営台帳へ記録
